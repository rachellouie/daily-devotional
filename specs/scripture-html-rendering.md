# Spec: Rich scripture rendering (HTML content-type) — verse numbers, chapter markers, structure

> **Status:** Spec only — not yet implemented. Decisions captured 2026-06-18.
> **Origin:** Manual visual review of the non-contiguous feature surfaced three
> display problems that all share one root cause — we fetch scripture as flat
> `content-type: text`, which gives us no styleable structure. This spec switches
> the fetch to `content-type: html` and renders that structure.

## Why this exists (the review findings)

Reviewing real readings ([`?date=2026-09-05`](http://localhost:3000/?date=2026-09-05)
etc.) exposed:

1. **Cross-chapter spans are invisible.** Job 22:21→23:1 just re-shows `[1]` with
   no signal the chapter turned over (we fetch with `include-chapter-numbers:false`).
2. **Verse numbers are unstyleable plain text** (`[1] [2]` baked into a text blob),
   so they can't be made subtle or optional.
3. **Psalms show a redundant "Psalm 32" line** in the body (API content) and poetry
   has no indentation.

All three are downstream of `content-type: text`. Fetching `html` gives API.Bible's
structured markup, which is **styleable and toggleable**.

> **Related but handled OUTSIDE this spec** (small, no spec needed, TDD directly):
> - **#1 — Non-contiguous heading bug:** card title shows only the first segment
>   (`Num. 13:1-3` instead of `Numbers 13:1-3, 21-30`). Fix = smart-collapse the
>   segment IDs via extended `passageIdToReference` in `lib/scripture.ts`.
> - **#3a — Whole-chapter Psalm heading:** when the whole psalm is read, the card
>   title should read `Psalm 32`, not `Psalm 32:1-11`. Detectable at parse time
>   (our passage ID is a bare `PSA.32` with no verses), independent of HTML.

## Decisions (from the 2026-06-18 grill)

| # | Decision | Choice | Rationale |
|---|---|---|---|
| Verse numbers | Toggle vs always | **Hidden by default + user toggle** | Cleanest default reading; numbers on demand. |
| Number style | When shown | **Superscript, muted** (`¹`, lighter color) | Reads like a printed Bible, stays out of the way. |
| HTML safety | Sanitize or trust | **Trust API.Bible, no dep** | Server-side fetch, fixed trusted vendor, no user input in the path. Document the assumption; CSP noted as optional hardening. |
| Chapter change | How to signal | **Subtle "— 23 —" divider** | API already emits `<h2 class="c">`; we style it. |

### On not sanitizing (the residual risk, on the record)

No user input reaches the injected HTML — passage IDs are generated by us from the
lectionary and fetched server-side over TLS from a fixed vendor. The only path to
malicious HTML is **API.Bible (or its CDN) being compromised**, or a TLS MITM.
Even then, `<script>` injected via `dangerouslySetInnerHTML` does **not** execute;
the narrow residual vector is attribute handlers (`<img onerror=…>`). Blast radius
is a single-user, no-secrets devotional reader. Probability low × impact low →
**accept the risk, no runtime dependency.** Optional future hardening: a
Content-Security-Policy header (Next config, no dep) that blocks inline handlers —
broader coverage than a sanitizer, cheaper. Out of scope here; noted in Risks.

## Grounded markup reference (verified via live fetch 2026-06-18)

API.Bible `content-type=html`, `include-verse-numbers=true`,
`include-chapter-numbers=true`, `include-titles=false`:

```html
<h2 data-number="32" data-sid="PSA 32" class="c">32</h2>   <!-- chapter marker -->
<p class="cl">Psalm 32</p>                                  <!-- redundant chapter label -->
<p class="q1"><span data-number="1" data-sid="PSA 32:1" class="v">1</span>Blessed is the one</p>
<p data-vid="PSA 32:1" class="q2">whose transgressions are forgiven,</p>
```

| Element | Class | What we do |
|---|---|---|
| Verse number | `span.v` (carries `data-sid="BOOK C:V"`) | Superscript + muted; hide when toggle off. |
| Chapter marker | `h2.c` (carries `data-number`) | Style as subtle `— N —` divider; **hide the first one per reading** (the card title already names the opening chapter). |
| Chapter label | `p.cl` ("Psalm 32") | Hide always — redundant with the card title. |
| Poetry / prose | `p.q1`, `p.q2`, `p.p` | Render as-is — we get indentation for free. |

> The chapter divider for cross-chapter spans is **emitted by the API**, not built
> by us — `<h2 class="c">23</h2>` appears at the 22→23 boundary. We only style it.

## Acceptance criteria

1. Scripture is fetched with `content-type=html` and `include-chapter-numbers=true`.
2. Each segment's HTML renders via `dangerouslySetInnerHTML` inside the existing
   per-segment structure; the inline `…` gap marker between non-contiguous segments
   is unchanged; the failed-fetch fallback view is unchanged.
3. Poetry/paragraph structure from the API is preserved (no `whitespace-pre-line`).
4. Verse numbers render as **superscript, muted** when shown.
5. Verse numbers are **hidden by default**; a user toggle (persisted like the
   translation choice) shows them. Toggling does not re-fetch.
6. A chapter change *within* a reading renders as a subtle `— N —` divider; the
   **leading** chapter marker of a reading is suppressed (card title carries it).
7. The redundant `p.cl` chapter-label line (e.g. "Psalm 32") is not shown.
8. No new runtime dependency is added; the trust-the-source assumption is documented
   in `lib/scripture.ts` near the fetch.
9. Mocked fetch tests use HTML fixtures; `toSegmentViews` (text/gap/fallback) is
   unchanged and still green.

## Vertical slices (tracer — green AND shippable at every boundary)

- **Slice A — HTML render swap.** Fetch `html`; render each segment via
  `dangerouslySetInnerHTML`; add scoped CSS wrapper; hide `p.cl` and the leading
  `h2.c`. Update fetch fixtures to HTML. *Ships:* readings now have real
  paragraph/poetry structure; no regression. Verse numbers visible+plain (interim).
- **Slice B — Subtle verse numbers.** Scoped CSS targets `.v` → superscript + muted.
  *Ships:* numbers read like a printed Bible.
- **Slice C — Chapter dividers.** Style non-leading `h2.c` as `— N —`. *Ships:*
  cross-chapter spans (Job 22→23) read correctly. Closes review finding #1.
- **Slice D — Verse-number toggle.** New persisted setting (cookie + server action +
  UI control paralleling `TranslationPicker`); default hidden; container class flips
  `.v` visibility via CSS (no re-fetch). *Ships:* the full "hidden by default + toggle"
  decision. Largest slice; sequenced last to de-risk.

## Out of scope

- Sanitizing the HTML / adding a sanitizer dep (risk accepted above).
- Content-Security-Policy header (optional future hardening — noted, not built).
- Per-verse linking / copy / audio (the `data-sid` makes these possible later).
- #1 heading smart-collapse and #3a whole-chapter Psalm title — TDD'd separately.

## Risks / open questions

- **`dangerouslySetInnerHTML` is a security seam** — see the risk write-up above.
  Decision: accept, document, leave CSP as a known lever.
- **Scoped CSS vs injected classes:** Tailwind can't reach API classes; this needs
  hand-written CSS (`globals.css` or a wrapper). Keep it scoped under one container
  class so it can't leak into the rest of the app.
- **Leading-chapter suppression** must be per-segment, not global — verify the
  first `h2.c` in segment 1 is the only one to hide, and mid-chapter segments emit
  no leading `h2.c` (confirmed for Job 22:21 start: no `22` marker).
- **Render-test gap persists:** the Vite 8/Rolldown JSX limitation still blocks a
  full DOM render test, so the literal superscript/divider styling is verified by
  eye, not by an automated render assertion. Logic (which classes, toggle state)
  stays pure-function testable.
